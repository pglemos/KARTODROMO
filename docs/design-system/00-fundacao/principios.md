# Princípios

Use estes princípios para decidir quando o guia não tiver a resposta pronta.

1. **Clareza na pista.** O cronometrista decide em segundos com a corrida acontecendo. A informação crítica (tempo,
   bandeira, posição, alerta) tem o maior contraste e o maior tamanho; o resto recua.
2. **Operação rápida.** Quem usa todo dia precisa de atalhos (F1–F11, Enter, Esc), poucos cliques e nenhuma
   confirmação desnecessária — mas confirmação **sempre** antes de ação destrutiva ou irreversível.
3. **Nada só por cor.** Todo estado tem também texto, ícone ou forma (daltonismo atinge ~8% dos homens).
4. **Uma regra para todos.** O mesmo componente se comporta igual em todo app. Se duas telas resolvem o mesmo
   problema de formas diferentes, uma delas está errada.
5. **Nunca tirar função do dia a dia.** Redesenho que esconde uma função operacional (ex.: o quadro da agenda da
   recepção na cronometragem) é regressão, mesmo que fique mais bonito. Conferir o fluxo operacional, não só o visual.
6. **Nativo onde é nativo.** Cronometragem, Recepção e Totem são programas Windows .NET instalados — nunca viram app web.
7. **Congelado é congelado.** O totem aprovado e o telão não mudam de aparência sem pedido explícito do dono.
8. **Valor sempre por nome.** Cor, fonte, espaço, raio e duração vêm dos tokens. Valor solto no código é defeito.
9. **Feedback sempre.** Toda ação mostra o que aconteceu (salvo, enviando, erro com o que fazer). Nada "some" calado.
10. **Desfazer é melhor que avisar.** Onde der, ofereça desfazer (estorno, restaurar passagem, reabrir equalização).
