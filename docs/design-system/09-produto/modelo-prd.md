# Modelo de PRD (documento de requisitos de produto)

> Um PRD por funcionalidade ou módulo. Curto: o que e por quê. O **como** da tela vai na
> [especificação de tela](../06-handoff/_modelo-especificacao-tela.md).

# {Nome da funcionalidade}

| | |
|---|---|
| Dono | |
| Status | ideia / aprovado / em construção / entregue (versão) |
| Apps afetados | Cronometragem / Recepção / Totem / Site / Admin / timing-ui / Tablet |
| Data | |

## 1. Problema
O que dói hoje, para quem, com que frequência. Evidência (fala do operador, número, foto).

## 2. Objetivo e métrica de sucesso
O que muda quando estiver pronto e como medir (tempo de atendimento, erros de caixa, reservas por semana…).

## 3. Quem usa
Perfis e contexto (de pé no balcão, olhando a pista, celular na fila…).

## 4. Escopo
**Entra:** … · **Não entra (agora):** …

## 5. Histórias
"Como {perfil}, quero {ação} para {benefício}." — com critérios de aceite verificáveis.

## 6. Regras de negócio
Numeradas (RN01…). Onde vivem (servidor / lib). O que acontece em exceções.

## 7. Telas e fluxo
Lista das telas (com link para cada especificação) e diagrama do fluxo.

## 8. Dados e integrações
Tabelas, APIs, ORBITS, SRVKART, Asaas, e-mail, R2.

## 9. Riscos e dependências
Operação ao vivo, horário de instalação, PCs afetados, migração de dados.

## 10. Lançamento
Versão, PCs, quem treina, como desfazer.
