# Public Site Production Stabilization Design

## Context

The public website currently mixes two implementations: Next/React routes and static `public/design/*.dc.html` documents rendered by a client-side runtime. `next.config.ts` temporarily redirects the canonical URLs to the design documents, which exposes unresolved template expressions to crawlers, fragments navigation and makes the existing automated tests validate a different application from the one served in production.

The Clube de Vantagens pages also present local mock data and non-persistent actions as if they were real customer operations. This must not remain ambiguous in production.

## Goal

Stabilize the public production surface on Cloudflare Workers so every canonical URL is served by the Next application, has route-specific metadata, is tested at desktop/tablet/mobile sizes, and never presents mock customer operations as real transactions.

## Chosen approach

Use the existing Next 16 + OpenNext Cloudflare application as the single production entry point. Remove redirects to `.dc.html`, route the public experience through the catch-all Next page, and replace React Router's browser-only routing with a pathname-based route resolver compatible with Next prerendering.

The legacy design documents remain in the repository temporarily as visual references, but they are no longer served as canonical pages. This avoids a risky all-at-once visual rewrite while immediately fixing indexation, routing and production integrity.

## Architecture

### Public route shell

- `app/[[...slug]]/page.tsx` resolves route metadata on the server.
- `app/PublicSiteClient.tsx` renders the public app without a white mount gate.
- `src/App.tsx` uses Next navigation state instead of `BrowserRouter`.
- All public route aliases are normalized in `next.config.ts` with permanent redirects.

### Metadata and discovery

- A central route metadata map provides title, description and canonical pathname.
- `generateMetadata` emits canonical, Open Graph and Twitter metadata.
- `app/sitemap.ts` publishes canonical routes.
- `app/robots.ts` allows canonical content and blocks `/design/` and admin-only paths from indexing.

### Clube de Vantagens safety mode

Until a real authenticated backend is implemented, customer-specific mock routes must not claim that data was saved, points were queried or rewards were redeemed.

- The public benefits and regulation content remains visible.
- Customer-specific pages show a clear beta/unavailable state with links back to the benefits page and WhatsApp.
- Fake registration, CPF lookup, profile save and redemption actions are removed from the production route resolver.
- No CPF-like mock data is exposed in the rendered application.

### Responsive and accessibility verification

Playwright covers all canonical public routes at 375, 768, 1024 and 1440 pixels. Tests verify:

- no unresolved `{{ ... }}` templates;
- no `.dc.html` canonical navigation;
- no accidental horizontal overflow;
- visible focus;
- reduced-motion behavior;
- route metadata and canonical tags;
- beta safety copy on customer-specific Clube routes.

### Cloudflare delivery

The existing OpenNext and Wrangler configuration remains the deployment mechanism. A GitHub Actions workflow runs typecheck, lint, unit tests, Next build and OpenNext build for pull requests. Pushes to `main` deploy with `npm run deploy:worker` using `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` repository secrets.

## Error handling

- Unknown public routes render the existing 404 page.
- Route metadata falls back to the site-wide title and description.
- Clube customer routes never display generated customer data.
- Deployment only runs after the complete verification job succeeds.

## Non-goals for this stabilization PR

- Building a complete authenticated loyalty backend.
- Recreating every static `.dc` layout pixel-for-pixel in React.
- Changing the admin application or D1 schema.
- Embedding or proxying the MyLapTime interface.

These are intentionally excluded because they require separate product and security specifications. The current change removes misleading behavior rather than replacing it with an unsafe rushed implementation.

## Acceptance criteria

1. Canonical public URLs no longer redirect to `/design/*.dc.html`.
2. Raw HTML and rendered pages contain no unresolved template expressions.
3. `/valores` permanently redirects to `/kart-locacao`.
4. Championship aliases permanently redirect to one canonical pathname.
5. Every canonical public route has unique title, description and canonical metadata.
6. Sitemap and robots files are generated by Next.
7. Customer-specific Clube routes clearly state that the portal is being prepared and perform no fake operations.
8. Pull requests run CI; `main` deploys to Cloudflare only after CI succeeds.
9. Playwright audits all canonical public routes at the four required viewport sizes.
10. The branch contains no credentials or account secrets.
